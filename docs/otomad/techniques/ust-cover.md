# 所有者の UST と MIDI から UTAU 音源でカバーを録る

- 所有者が人力で耳コピした UST（歌）と MIDI（全パート）があれば、自動の採譜は使わない。UST を dtm に読ませて声を `roze` などへ替え、ハモリは MIDI のトラックへ主旋律の歌詞を当てて同じ道で録る。

## やり方

- 譜面の置き場所: 所有者の耳コピは別の PC の `C:/Users/frgk2/Music/_own/自作/界隈曲` にある（[docs/research/transcription-eval.md](../../research/transcription-eval.md)）。この PC に無ければ、自動の採譜を始める前に所有者に写してもらう。あねもねぐりっちは `221017.ust`・`221017.mid`・`歌詞.txt` の組だった。
- 原曲との位置合わせ: MIDI の歌トラックの音と、原曲の声の stem の基本周波数が合う秒数を探す（あねもねぐりっちは MIDI の 0 拍目が 0.69 秒）。
- 声だけの MML: 見えない Edge で DTM を開き、`parseUst` の結果を `daw.applyUstParsed([u], 0)` で入れ、`daw.getMML().full` を受け取る。`@@0 <声> かな` の声を `roze` に、`#drum=` を `none` にして `loadMML` し、`studio.startWavRecording()` で実時間に録る（作例 `scratch/anemone/work/rec.mjs`）。
- 延ばしの母音: UTAU の UST は延ばしを「くうう」「まああ」と母音で書くので、そのままだと音ごとに言い直す。行のよみ（漢字=よみ）に音を順に当て、よみに当たらない母音（直前と同じ母音）だけを `ー` にする。母音が同じだけで `ー` にすると「しぐれわ**あ**め」の「あ」まで延ばしになる。
- ハモリ: MIDI の音の頭に主旋律の音の頭があればその歌詞、前のハモリの音と続いていれば `ー`、途中から入るなら主旋律の歌詞を当てて UST を書き、同じ道で録る。所有者の `歌詞.txt` はこのハモリの歌詞と一致した。
- ずれ: 録音の中の 0 拍目は回ごとに 0.9〜1.5 秒と違う。区間ごとに測ると録音は 0.04% 速いので、`rubberband=tempo=0.9996` で伸ばしてから切る。区間の途中で 0.4 秒跳ぶことがあり（合成の遅れ）、その回は録り直す。
- 手元の UTAU 音源（dtm に無い声。例: 束音ロゼ（華）の連続音）は、OpenUtau の書き出しコマンドで UST をそのまま歌わせる。音源フォルダを `tmp/openutau-bin/Singers/<英字の名前>` に写し（zip の名前は cp932 なので展開時に直す）、`OpenUtau render --input <ust> --output <wav> --singer <名前> --phonemizer OpenUtau.Plugin.Builtin.JapaneseVCVPhonemizer --renderer WORLDLINE-R`（`DOTNET_ROOT` は `tmp/dotnet`）。延ばしの音は歌詞を `+` にする。実時間の録音でないので、ずれも揺れも無い。
- 声の大きさ: 原曲の声の stem と伴奏のラウドネスの差（あねもねぐりっちは −8.6 LU）を測り、合成の声は 1.5 LU 前へ出す。

## 試した作品

- anemone（11-06、あねもねぐりっち 束音ロゼ版）: 主旋律の高さの一致 0.84（延ばしを直す前は 0.74）。行ごとの音声認識の一致は平均 0.63、最後のサビ（全音上がる所）で下がる。評価は未確認。

- anemone 第3版（11-06）: 主旋律を華（OpenUtau、JA VCV）にした。行ごとの音声認識の一致は dtm の roze 0.63 → 華 0.90。

## はまりどころ

- MIDI を Surge XT で編曲するときは、パッチを1音ずつ鳴らして高さを測ってから使う（作例 `scratch/anemone/arr/patchtune.py`）。Magic Music Box は1オクターブ上で約 10 セント低く、Piano Remains はわざと −90 セント、Sub 2 は1オクターブ下で鳴る。所有者は「オクターブ高い」「半音ズレている」とすぐ気づいた。テープの揺れも、細かい揺れ（毎秒5〜6回、0.3〜0.5 ms）だけで ±20 セントを超えるので、音程のあるパートには掛けない。
- カバーの伴奏を MIDI から作り直すときも界隈曲の音で作る。Surge の工場プリセット・サイドチェイン・長い残響の「錆びたオルゴール」は「方向性が外れている」「高音によっていて耳が痛い」と言われた。素の Init Square・Saw・Sine を左右別々に鳴らし（作例 `scratch/anemone/arr/render_kaiwai.py`）、原曲と同じ帯域の物差しで比べて寄せる（`arr/mix_kaiwai.py` の参照 EQ）。矩形波・鋸波の和音は 2〜4 kHz を原曲より 7 dB 持ち上げていた。
- pedalboard の Limiter（JUCE）は天井を 0 dBFS へ持ち上げる補正を入れる。天井を −1 にしたつもりで真のピークが +3.4 dB になった。後で天井ぶん下げ、真のピークは ffmpeg の ebur128 で測る。
- 音源の readme が利用の範囲を狭めていることがある（華は非商用のみ）。統一ガイドラインより音源の readme を見る。

- `pnpm build` は整形で改行コードだけ変えたファイルを残すことがある。録音のために build したら `git status` を見て戻す。
- Demucs は 44.1 kHz で書き出す。48 kHz のつもりで間引くと、高さが +1.47 半音、時間が 0.92 倍にずれて見える（調律が半音ずれていると勘違いした）。
- 見えない Edge は親を止めても子が残り、同じプロファイルの次の Edge がすぐ終わる。プロファイルの場所でまとめて止める。node の `spawnSync` から PowerShell へ渡す文に `"` を入れ子にすると壊れて、何も止まらない。終わりの片付けを遅らせると、次の回の Edge を止めてしまう。
