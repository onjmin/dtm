# カバーの伴奏を原曲の質に寄せる

- カバーの伴奏を、原曲の歌なし音源と区間ごとに数値とスペクトログラムで並べて確かめる。差は音色より先に「欠けているパート」から埋める。
- 所有者に渡す前に、この確かめと直しを済ませておく。所有者に聞き比べてもらう前にやる仕事で、聞き比べページを渡しても代わりにならない。

## やり方

### 1. 時刻を合わせる
- 原曲の歌なし音源（`ref/orig_inst.wav` など。測るためだけに使い、git には入れない）を手元に置く。自分の版の小節が原曲の何小節にあたるかを、区間ごとに決める。
  - 前置きや延長で小節がずれる時は、ずれる所ごとに書く（例: 原曲 0〜43 小節は +17、44 小節から +25）。
- 残りの秒のずれは、和音の chroma の相互相関で測る。ずれの向き（＋か−か）を一度確かめる。向きを逆に取ると、拍の中の形の比較が全部くずれる。

### 2. 区間ごとに数値で並べる
- `scripts/otomad/analysis/check_vs_orig.py --orig 原曲.wav --ours 伴奏.wav --bpm … --sec "A1=8-28,…" --map "0:17,44:25"`
  - demucs（htdemucs_6s）で両方を分ける。区間ごとに次の 4 つを原曲との差で出し、±3 dB・±3 音を超えた所に ★ を付ける。
    - 6 帯の割合（40–250・250–500・500–1k・1–2k・2–4k・4–16k Hz）
    - 同時に鳴る音の数（C3–C6 で、いちばん大きい音から 15 dB 以内の音の数）
    - 和音−ドラム
    - ベース−ドラム
- 大きさに依らない比で比べる。帯域は「全体に対する割合」、釣り合いは「stem どうしの差」で見る。
- 全区間で ★ が消えるのを目安にする。消せなかった所は、渡す時に表にして伝える。

### 3. スペクトログラムを目で見る
- 同じスクリプトが、区間ごとに原曲と上下に並べた図を書く。2 枚は大きさをそろえ、同じ基準と同じ色の幅（−75〜0 dB）で塗る。基準を 1 枚ずつ取ると、薄い所が濃く見えて比べられない。
- 見る所:
  - 中域（250 Hz–2 kHz）に線が詰まっているか、すかすかか。
  - ベースに倍音の線が何本あるか（128–512 Hz）。
  - 2–4.5 kHz に拍ごとの縦の筋（キックの頭・ハット）があるか。
  - 8 kHz より上が途切れず続くか。
- 数値で合っていても、図で穴が見えたら直す。所有者は図で差を見つけた（ぽぽりん穴「真ん中がすかすか」）。

### 4. 欠けたパートを先に探す（音色はその後）
- 原曲の stem（other・guitar・piano）を basic-pitch で採譜し、手元の MIDI に無いパートを探す。
  - 耳コピ MIDI には、和音の刻み（低い根音を伸ばし、上の音を裏で刻む・サビは 16 分のシンコペーション）が入っていないことが多い。
- 足す時は、すでにあるトラックと同じ音（同じ音名が 70 ms 以内に始まる音）を外す。そうしないと、イントロのプラックやオブリガードを二重に鳴らしてしまう。
- 和音の音域が原曲より高い時（C#5–B5 しか無い等）は、1 オクターブ下に重ねる。

### 5. 帯域と拍の穴を直す型
- **中域の穴**: 4 の欠けたパートと低い和音で埋める。足りない帯域は和音の側にだけ EQ を当てる（350 Hz・1.4 kHz を上げ、700 Hz を下げる、など）。
- **ベースの倍音**: 基音だけの音色を、倍音のあるもの（例: SGM 87）に替える。左右には広げず、真ん中に置く。
- **2–4.5 kHz の拍ごとの穴**: 原曲のキックには「カチッ」という頭がある。15 ms のノイズを 2–5 kHz の帯域に通して、キックに足す。裏のハットを 3.2 kHz で持ち上げ、平らに鳴り続けるシェイカーは下げる。
  - 圧縮が原因に見えても、まず打楽器の頭を疑う（比を 1.0 にしても穴は残った）。
- **ポンピング**: キックで和音を引っ込める処理は Suno 由来なので外す。
- **伴奏全体の EQ の基準**: 原曲に合わせる。Suno に寄せた版を基準にしない（2–16 kHz のシャリ感が移る）。
- **200 Hz 以下の左右**: 側成分は 200 Hz より上だけに残す。

### 6. 大きさを変えずに直す
- 曲全体で大きさを合わせ直す段は使わない。決まった値に固定する（ぽぽりん穴の `freeze.py`）。替えた楽器の段だけ測り直す。
- 直した版は、基準の版と 4 小節ごとに大きさを比べる。直したあとで全体が小さくなっていないかを、必ず確かめる。
  - パートを足すと圧縮が強くかかり、ほかの所が沈む。全体を戻す時は、ミックスの前の伴奏で dB を足す。
- 所有者が前の版のほうを気に入った区間は、その区間だけ前の版から差し込む。大きさは A1 との比を保ち、継ぎ目は 8 分ぶん重ねてつなぐ。

### 7. 渡す時
- 直した所と、残った差（区間・帯域・dB）を表にして伝える。わざと原曲から離した所（所有者の好みで残した区間など）は、そう書く。

### 8. 部品の wav は切れない形式で書く
- soundfile の `sf.write(path, x, sr)` は、形式を言わないと WAV を 16 bit の整数で書き、±1 を超えた波形を黙って切る。合成した楽器や stem などの中間の部品は、必ず `subtype='FLOAT'` で書く。
- 「ざらつく・汚い・割れる」と言われたら、音色を疑う前に、部品ごとの形式・ピーク・0.999 以上の標本の割合を見る。

### 9. 役ごと・stem ごとに並べて見る
- 混ぜた後の数値が合っていても、土台の差は見えない。原曲の stem と自分の部品を、ドラム・ベース・和音側に分けて上下に並べる。
  - ベース: 基音を FFT で確かめる（原曲と同じオクターブか、音を伸ばしているか）。耳コピ MIDI のオクターブは当てにならない。
  - ドラム: 16 分ごとの帯域別の大きさで、打ち方と尾の長さを見る。
- 和音側の stem は、まとめずに 1 本ずつ見る。demucs の guitar が、ギターではなく主役の和音シンセのことがある。
- パートの名前で音量を頼まれたら、下げる前に「何秒のどの音か」を確かめる。所有者の呼び名と自分の部品名は一致しない。

### 10. 和音の音符を確かめる
- 減衰の速い音色から伸びる音色に替えると、隠れていた音符の食い違いが聞こえるようになる。替えたら次を数える。
  - 和音側の音符どうしが半音で並ぶ 16 分の数。
  - 伴奏が休む所（ブレイク）で鳴っている音。
  - 原曲と 8 分ごとの chroma を比べて、一致の低い所。
- よくある原因は 3 つ。弾き直しが前の和音の音を持ち越す、空の拍に「前の和音」を入れてしまう、1 オクターブ下の重ねが隣の音と半音になる。
- 低い音域（E3 より下）には、和音のオクターブ下を重ねない。3 度が濁る。

### 11. 厚みを測る
- 帯域の割合が合っていても「薄い」と言われる。次の 3 つを原曲・前の版と並べる。
  - 埋まり: 200 Hz–5 kHz で、山から 30 dB 以内の周波数の割合。
  - 倍音の谷: 隣り合う倍音の間の深さ。
  - 帯域ごとの山−底: 時間方向の 90% 点と 10% 点の差。原曲は 1.6 kHz より上が鳴りっぱなしで 8〜12 dB、打った瞬間だけ鳴る伴奏は 16〜20 dB になる。
- 残響を足しても埋まらない。効いたのは、和音側に帯域ごとの上向き圧縮（OTT、深さ 45〜60%）を掛けることと、シンセのフィルターを伸ばしで閉じすぎないこと。
- 楽器や混ぜを替えたら、毎回これを測り直す。

### 12. 採点モデルで判定してから渡す
- 自分は音を聞けないので、渡す前に学習済みの採点モデルに掛ける。
  - 制作の質: audiobox-aesthetics の PQ（1〜10）。
  - 原曲との近さ: LAION-CLAP の埋め込みの余弦（同じ区間どうし、約 10 秒）。
- 役ごと（完成音源・伴奏・ドラム・ベース・和音側）と区間ごとに、原曲・前の版・今の版を並べる。点が下がった版は渡さない。
- 変更は「土台の版＋ 1 つずつ試して、点が上がった物だけ採る」で選ぶ。土台は、部品の足し算で正確に再現できる版にする。
  - 探索に使っていない区間でも同じ差が出るかを、最後に確かめる。
- 伴奏全体か完成音源で採点する。和音側だけを原曲の和音の stem に寄せると、stem の点は上がっても伴奏全体は良くならず、質が落ちた。
- 採点はモノラルなので、左右の広がり・区間どうしの音量・音割れ・厚みは別に確かめる。
- 点が上がっても良く聞こえる保証は無い。渡す時にそう伝える。聞き分け・音色選び・DAW での仕上げを所有者に頼まない。

### 13. Vital を Python から鳴らす
- pedalboard の `load_plugin` で Vital.vst3 を読み、MIDI を渡して全曲を書き出せる。音色は `raw_state` の中の JSON を書き換えて、初期状態から組む。
  - 入れ物は VC2 → `<IComponent>` の JUCE 独自 base64 → VstW／CcnK／FBCh の後ろ。書き戻す時は、大きさの欄を 3 か所直す。
  - モジュレーション（env_2 → filter_1_cutoff など）と、自作の波形（2048 点）も入る。
  - エンベロープの時間は値の 4 乗が秒、LFO とディレイの速さは log2(Hz)、フィルターの cutoff は MIDI ノート番号。
- キットを画面で読み込む種類の音源（SSD5 など）は、読めても無音になる。

## 試した作品

- ぽぽりん穴（ヤツメ穴のカバー、A49）
  - A48 で所有者がスペクトログラムを見て「真ん中がすかすか」と指摘した。原因は、和音の刻みのパート（ギター）が無かったことと、和音の音域が高すぎたこと。
  - 直した結果（原曲との差）:
    - サビの 250–500 Hz: −6.9 → −3.8 dB
    - A1 の 1–2 kHz: −4.5 → −0.4 dB
    - 4–16 kHz: +3.7 → ±1 dB
  - 残った差:
    - サビ系の 250–500 Hz: −2〜−4 dB
    - サビ系の 1–2 kHz: −3 dB
    - 同時に鳴る音の数: 4〜6 少ない
  - 所有者の評価待ち。
- ぽぽりん穴（A55〜A66、2026-11-25）
  - 所有者の指示は「楽器とか音色とか大幅に変えて、人間が mix したレベルに」。土台（A55）、和音側の楽器（A56）、Vital（A64）と作り替えるたびに「変わっていません」「ざらついている」「厚みがない」「原曲に届いていません」と返った。
  - 採点モデルに掛けると、作り替えは全部後退だった（伴奏の原曲との近さ）:
    - A54（作り替える前）: 0.79、質 7.91（原曲の質 7.90）
    - A55〜A65: 0.70〜0.75
  - A54 を土台に、上の 12 のやり方で選び直した A66: 伴奏 0.87・質 8.02、歌入り 0.81・質 8.08（A54 は 0.79・7.99）。所有者の評価待ち。
  - 途中で見つけた傷: A56〜A59 は和音の部品が保存時に音割れしていた（8）。A65 で足したドラムの部屋の響きは、質を 0.6 点落としていた。

## はまりどころ

- 自分の版にギターがあると、demucs は和音の大半を guitar に入れる。stem ごとの割合で音量を判断しない。和音は other・guitar・piano を足してから比べる。
- 足したパートが大きすぎると圧縮を叩き、ドラムとベースが 7〜9 dB 沈む。それで足したパートの音量を変えても、差がほとんど出なくなる。
- 評価用の AI は、使い方で当たり外れがある。
  - A49 までは、CLAP の距離と Qwen2-Audio の点数が所有者の判断と合わず、上の比と図のほうが 3 つの指摘と一致した。
  - A55〜A65 では逆に、比と図・帯域・厚みのどれも後退を示さず、CLAP の近さ（原曲の同じ区間と、役ごと）と PQ だけが所有者の不満の続いた版を全部低く採点した。
  - どちらか一方に頼らない。比と図で穴を探し、採点モデルで版の良し悪しを見る。
- 「大幅に変えて」と言われても、良かった版を捨てて全部作り替えない。替えるたびに前の版と採点で並べ、下がったら戻す。
- 音色への不満が同じ楽器の調整 1 回で消えなければ、原因を別の段（保存の形式・混ぜ・ほかのパート）にも探す。楽器のせいと決めて調整や差し替えを重ねない。
- 原曲の 1 発の平均に形を合わせたドラムの標本は、採点では元のドラムより悪かった。stem から採った平均には、ほかの音と分離の濁りが混ざる。
- 図の正規化のせいで、低域の左右にもやがあるように見えることがある。数値で確かめる。
- 区間を聞き比べるページを作っても、聞く仕事を所有者に戻すだけになる。自分で測って直してから渡す。
