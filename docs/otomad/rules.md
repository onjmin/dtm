# 音MAD・BB劇場の決まり（所有者の基準）

作る前に毎回読む。所有者の指摘で基準が変わったら、ここを直す。直した日と元になった指摘は、その項目の括弧とコミットの文に書く（変更の記録を1か所に足す表は、複数の PC で作るとぶつかるので置かない）。

技の中身は [techniques/](techniques/README.md)、型ごとの作法は [genres/](genres/)、根拠の測定は [research/](research/) にある。ここには「何を守るか」だけを書く。

## 1. 振り切る軸は1〜2つ

- 1本ごとに「振り切る軸」を1〜2つ決め、それ以外は普通にしておく。軸は作品台帳（[works/](works/README.md)）に**作る前に**書く。
- 台帳の型: 狙い（1文）／振り切る軸／普通にしておくところ／物語と構成／緩急計画。
- 全部を盛らない。同時に目立つ要素は2つまで（文字・人・流れる帯・札で4つになった dande3 の B は失敗）。

## 2. 緩急

所有者の評価と、ネットの講評（[research/inmu-cookie-staging.md](research/inmu-cookie-staging.md) に出典）から。

- 区間ごとの密度に差を付ける。拍に合っていても、全編同じ密度だと疲れる。音（層の数・音量）と映像（動き・切り替え）の**両方**で、少なくとも3段に分ける。文字PVの作例（dande3）は、映像には段があったが、音は −11 dB で平らだった。
- いちばん強い所の直前で引く。止める、字を消す、地だけにする、無音の1拍を入れる、など。強い地や派手な見せ方は最初から全部出さず、後半まで取っておく。ドロップの前で伴奏を全部止め、台詞の掛け合いだけ置いて1拍の無音から落とす作り（yatai1）は「確実に良い」と言われた（所有者 11-07）。
- 緩急は差であって振れ幅の最大化ではない。極端な効果の乱発は大味になる。
- 単色の地は、寄り・引きや位置を変えないとスライドショーに見える。
- 割る回数は型が決める（日常・番組ものは長回し、型パロディは元の編集の速さ、一発合成はほぼ割らない）。[genres/bb-theater.md](genres/bb-theater.md)。

## 3. 物語性

- 筋書きは、人の出入りと関係の変化で作る。客が1人ずつ来る → 「ん？」で暗転 → 戻って全員で回す、という作例（dande2）は「オリジナルにしてはかなり良い演出」と言われた。
- オチの台詞の前には1拍の間を置く。
- 物語で作る BB劇場の型（題名で目的を言い切る・40〜60% でジャンルを乗り換える・真顔の場面・3回戻る決まり文句・二段オチ）は [genres/bb-theater.md](genres/bb-theater.md)。
- 人物は界隈の持ち役のまま動かす（RRM は刃物と「お覚悟を」、NYN は店、UDK は家）。
- **話は1本ごとに起承転結で組む**（所有者 11-03、cm20「各話の起承転結が分かりにくい」）。誰が何を望み、何が起きたかを、人物の行動と場面の変化で伝える。
- **動画の中に題名を入れない**（所有者 11-03、cm22「後でタイトルを変えるかもしれない」）。頭や終わりの題字、作中の表紙も作らない。題名は台帳と投稿欄にだけ置く。
- **指摘の言葉や作り方の用語を画面に出さない**（所有者 11-03、cm21 で「起・承・転・結」を印にして出した。「なぜ言ったことをそのまま文字として埋め込むのか」）。指摘は作り方への注文で、視聴者に見せる字ではない。
- **人物の移動方向は顔の向きと合わせる**（所有者 11-03、cm20「向いている方向と反対向きに歩く」）。絵ごとに向きを確かめ、動かす方向で反転する。向きは一覧の縮小絵で判断せず、頭を切り出して大きく見て決める（所有者 11-08、bb32 で KMR・遠野・MUR の向きを縮小絵から逆に読み、2 回ムーンウォークになった）。
- **高速の色替え・乱数の配置で混乱を表さない**（所有者 11-03、cm20「ポリゴンフラッシュみたいなシーンがあって意味不明」）。視聴者の負担にもなる。混乱も、誰が何をしているか分かる画で見せる。
- **配役はキャラ同士の関係から決める**（所有者 11-03）。同じ作品の共演（NYN と ICG、RU と UDK）、同じアバター（UDK と RI は魔理沙役）、一家や一派（RIM 一家・UDK 姉妹・ALC 一派）を調べ、誰と誰がなぜ組むかを台帳に書く。人数を並べるだけにしない。所有者が挙げた例をなぞらず、タグの共起と百科と作品そのものを自分で調べ、そこから企画を決める（所有者 11-03「私が言ったものしか引き出しになく自分で調べる行為が欠如している」。[research/cookie-relations.md](research/cookie-relations.md)）。
- **バトルは「導入 → 起承転結（バトル → 涙 → バトル → クライマックス → オチ）」で組む**（所有者 11-02）。伏線を散りばめて回収する（例 bb12: 奥にいた KMR → 裏切り、銃の禁止 → 素手で勝つ、床に残ったアイスティー → 涙の場面で飲む、来なかった KEN → 最後に来て「やです」）。
- **調べるときは数2つで済ませず、台詞・音・視聴者の反応まで見る**（所有者 11-01、bb2 への指摘「分析が足りない」）。
- **名作はコマ送りで作りを見てから手本にする**（所有者 11-02「本当に名作を参考にしたのか？」）。数（カット・コメント）だけで真似ない。止まった立ち絵では動きのある名作（実写 BB の打ち合い・MMD の演技）に並ばないので、道具で質を出せる型（一発合成など）を選ぶ。筋は字幕の説明より、物（名刺・新聞）と行動で語る。スタッフのエンドロールは要らない。
- **音で勝負する曲は静画か1枚絵にする**（所有者 11-07、yatai1「映像のクオリティは低いから、静画か、１枚絵に変えた方がいい」）。立ち絵の口パク・スペクトルの街並み・写真の暮れで動かしても質は上がらなかった。手本の Pump inm Up・Minm Control も絵1枚（[research/hit-otomad.md](research/hit-otomad.md)）。動かすのは、手描きや 3D など道具で質を出せるときだけ。1枚絵は NCS のトップ絵の作り（暗い単色の地・光の筋・中央の輪・二色に落とした主役）。動かすなら素材そのもの（くるくるNSDR の円盤を拍に合わせて回す）だけにする（所有者 11-07）。
- **作りの質で名作に並べる**（所有者 11-02「全然名作に比肩しない、低品質」）。BGM を合成で済ませない（素材フォルダの【INM】楽曲.zip の実際の曲を場面ごとに選ぶ。展開は作業フォルダへ）。床を作り物の透視で描かない（写真の背景を層の視差で動かし、背景をぼかして人物を浮かせる。`songs/bb/film2d.py`）。効果は手描きの図形でなく GB/BB の効果素材（爆発・メガシンカ・カレービーム・集中線）。雨・光の筋・埃・粒子・色・黒帯で画を作る。音量は `loudnorm`（−16 LUFS、真のピーク −3 dB）でそろえる。
- **源の映像が暴行・虐待の場面の素材は使わない**（KBTIT の「誰も助けにこねぇぜ」「だまれ！」「大人しくなぁれ」など）。BB の切り抜きと、文脈の無い語録だけを使う。
- **緩急は波で作る**（所有者 11-02「名作はもっと緩急やストーリーが練られている」）。速い戦い（40〜70 カット/分）と静かな筋・笑い（〜10 カット/分、無音に近い）を 30〜120 秒ごとに入れ替える。頭は速い先見せ → 静かな導入。決着の直後は無音、涙は決戦の後。後日談は短く。
- **映画の作法で見せる**（所有者 11-02）。シネマスコープの黒帯、場面ごとの色、決め所のスロー、エンドロールとその後の一場面。
- **ウケる所を狙って置く**（名作のコメントの測定、[research/battle-inmu.md](research/battle-inmu.md)）。15〜25% に「は？」の壊れ方、戦いの途中に関係ない場面への切り返し（草）、敵を倒した後の止め絵（つよい）、2回以上の語録（合唱）。
- **ニコニコ風のコメント（弾幕）を動画に描かない**（所有者 11-02）。投稿先のニコニコには本物のコメントが流れるので、作り物を描けば重なって邪魔になり、視聴者が書くはずの反応（は？・草・合唱）を先に取ってしまう。名作のコメントの測定は、反応が来る場所を知るためのデータで、作品の作りではない（名作の動画にコメントは焼き込まれていない）。作るのは反応を誘う場面までにして、反応は本物のコメントに任せる。メタな人物（画面の外が見える NEL など）は、カメラに話しかけるだけで本物のコメントと掛け合いになる。
- **バトルは対戦ゲームの枠に入れず、普通の戦いとして見せる**（所有者 11-02）。体力ゲージ・ROUND・VS 画面・コンボ数の札は間が延びる。
- **題名の「☆」は、クッキー☆の人物が出る作品だけに付ける**（所有者 11-01）。淫夢だけの作品には付けない。

## 4. 素材

- **作った素材（ドット絵・背景・描き出しのスクリプト）は asset リポジトリ（`C:\_own\git\asset`、onjmin/asset）に置いて push する**（所有者 11-08、海鬼月のドット絵を dtm の `assets/` に置いて「違います」）。dtm の `assets/` はアプリに同梱するキャラのアイコンだけ（[assets/README.md](../../assets/README.md)）。
- 所有者が指定したフォルダ（今は `D:\音MAD素材` ＝ `SPEECH_MATERIAL_DIR`）の中を見て台詞を選ぶ。前に使った抜き出しだけで済ませない。
- **作品の中では淫夢とクッキー☆を混ぜてよい**（所有者 11-01）。同じ話に両方の人物を出す（bb6〜bb9）、実写と絵を重ねる、もできる。
- **素材の置き場所はジャンルで分ける**（所有者 11-01）。混ぜるのは作品の中だけで、置き場所は混ぜない。
  - 1つの素材は1つのジャンルのフォルダ（`淫夢/`・`クッキー☆/`・`エア本/`・`AI/<ジャンル>/`）にだけ置く。「bb8 用」のような作品ごとの寄せ集めフォルダや、`淫夢クッキー☆/` のような混ぜたジャンルを作らない。
  - 作品は、それぞれのジャンルのフォルダから読む。作業フォルダへ写すときも、写し先の中をジャンルで分ける。
  - 両方のタグが付いた素材は、主な人物のジャンルに置く（迷ったら `bb_fetch.py` のタグの順。`get --genre` で直す）。
- 台詞の声は、系統（同じメーカー・シリーズ・演者）がそろうと声質・録音の質・演技の型がそろって曲がまとまる（サムソン3本の例）。これは目安で、決まりではない。混ぜるときは寄せ集めに聞こえないか聴いて確かめる。
- 知られている語録・空耳を核にし、その系統で「型」になっている台詞で流れを組む（[research/inmu-kousatsu.md](research/inmu-kousatsu.md)）。
- **服装はそろえなくてよい**（所有者 11-01）。同じ人物でも場面・技ごとに別の BB（服・姿勢の違うもの）を使う。
- **各キャラの持ちネタ（語録・持ち役）を随所にちりばめる**（所有者 11-01）。
- **手元に無い人物の絵は、代用で済ませず作る途中で探す**（所有者 11-03、cm18 で4人を丸で代用した）。手元 → `bb_fetch.py search` の順に探し、無かったときだけ探した場所を添えて報告する。
- **BB素材は場面に合わせて使い分ける**（所有者 11-01）。MUR・KMR・野獣先輩などはパックに姿勢（立つ・座る・前のめり・背面・椅子で腕組み・跪く）、表情、BB動画が大量にあるので、全編を同じ立ち絵で通さない。歩く場面は背面、待つ場面は座る、詰められる場面は前のめり、落ち込む場面は背中の長回し、のように場面ごとに選ぶ。探し方は [bb-flow.md](bb-flow.md) の「1. 探す」。
- エージェントが集めた BB素材は `AI/<ジャンル>/` に置く。所有者が手で置いた素材には書かない（[bb-flow.md](bb-flow.md)）。

- **先に作った旋律へ声を無理に曲げない**（所有者 11-03、cm22「声のピッチをメロディっぽく操作しているのはどういう意図？違和感」）。声の抑揚と語尾の高さを測り、伴奏を声に合わせる。元の抑揚を保ったまま音階へ寄せるピッチ調整はしてよい（所有者 11-05、cm24「台詞イントネーションをピッチ調整する等」）。
- **素材の声を主役にする**（所有者 11-05、cm24「シンセによりすぎて元の素材の良さが失われてる」「もっと台詞イントネーションの頻度を増やしたほうがいい」）。声を母音のシンセにして言葉を消さない。
- **一転攻勢は最後の盛り上がりだけ**（所有者 11-05、ENU☆「一転攻勢は最後の盛り上がりパートだけです」）。後半の 2 番ごと替えない。最後のサビで声・伴奏・打楽器・絵を丸ごと替え、音圧も上げる。作り方は [techniques/ichiten-kousei.md](techniques/ichiten-kousei.md)。
- **ロイドの行と語録の行を混ぜない**（所有者 11-05「Roid系にちゃんと発音させたいのか、言わせたい語録を優先するのかちぐはぐ」）。替え歌はロイドだけで発音させ、語録は原音を主役にする。同じ言葉を両方で重ねない。
- **ドット絵は整数倍だけで拡大する**（所有者 11-05「拡大の仕方がまずくゆがんでいる」）。描き出しの倍率を測って 1 点へ戻し、全コマを同じ枠で切る。カメラの拡大も点を崩す。
- **伴奏も全パート素材で鳴らす**（所有者 11-05、手本 LAB=01☆ sm32354228）。合成音や原曲の音色を混ぜない。手順は [techniques/material-drums.md](techniques/material-drums.md)。
- **ひどい音源はモーラごとに直す**（所有者 11-05「ひどい音源は、モーラごとに分割して、適切な補正＆ピッチ調整＆ノイズ抑制をしたほうがいい」「HSKの音声とかも」「おいゴルァ免許見せろは環境音をクリッピングしたほうがいい」「素材の質によっちゃピッチ調整すると耳障りの音」）。環境音を引いて言葉の間を切り、モーラごとに音量と音高を合わせる。短い語録を引き伸ばさず、話す速さを保って繰り返す。
- **使った素材のアイコンを音に連動させて出す**（所有者 11-05）。声だけでなくドラムと伴奏も全編で。アイコンを文字や空欄で済ませず、BB や手元の絵から切り抜く（「HRNR、JUNのアイコンもBBから切り抜け。なぜ毎回空欄にするんだ」）。
- **ドラムも素材で作り込む**（所有者 11-05）。クッキー☆の場面はナイフの音などの効果音から選び、一転攻勢は淫夢の打楽器にして、打つたびに対応する BB かアイコンを出す。
- **歌は声が負けない所まで前へ出す**（所有者 11-05、ENU☆「声がだいぶかきけされています」）。音量だけでなく、子音・フォルマント・残響・オクターブユニゾンで太くする。ロイド（mgroid・nynroid・motroid、淫夢の50音）も使い、替え歌を検討する。
- **PV の色合いは原曲の雰囲気に合わせる**（所有者 11-05「エヌの雰囲気でPVの色合いを調整したほうがいい」）。構図は真似ないが、配色は原曲を測って合わせる。
- **高音を削る**（所有者 11-05「ハイの部分をフィルタで削ったほうがいい」）。効果音の打楽器は高音が多い。手本の動画と帯域ごとに比べる。
- **カバーは原曲の PV を再現しない**（所有者 11-05、ENU☆「エヌのPVをまねする必要はない」「再解釈して構築しなおしたり」「音MAD特有の図形移動を組み合わせたりする」「文字PVだったりも」）。原曲の映像は題材の読み替えに使い、図形移動・文字PV で組み直す。
- **ドット絵を新しく描くより、所有者の素材と BB を使う**（所有者 11-05、ENU☆「新規で書いているドットがクオリティ低すぎ」）。絵が無い人物は字だけで見せてよい。
- **MV は映像を作り込む**（所有者 11-05、cm24「MV演出も映像を凝ってほしい」「挑戦的でハイセンスな映像」）。立ち絵を窓に並べて終わりにせず、作品ごとに映像の仕掛けを1つ考える。界隈曲の MV（あめふらし）の水準を下回らない。
- **切り抜きは全コマ調べ、順再生だけで使う**（所有者 11-03、cm22「文字が表示されているフレームがあります」）。一覧の10枚で判断しない。動画の区間の札が混ざる。端で逆再生に折り返すと歩きが逆向きになるので、ループは周期を測るか、拍で切り替える。

- **所有者が原曲 PV を模写したスプライトは、原曲の振りどおりに使う**（所有者 11-07、あねもねぐりっち「MV があねもねぐりっちの PV とあっていない」「原曲とキャラのしぐさが乖離している」）。PV をコマで測り、どの区間で目を閉じる・揺れる・手を挙げるかを合わせる。跳ねは拍に合わせる（「BPM と同期がとれてない」）。「PV を再現しない」は構図と題材の話で、模写の素材の振りはこちらが優先。作り方は [techniques/pv-pixel-cover-mv.md](techniques/pv-pixel-cover-mv.md)。
- **グリッチは画面でなく人物の絵に掛ける。カメラは固定**（所有者 11-07「画面にグリッチをかけるのではなくキャラの絵にグリッチをかけるのが狙いでは」「ゆっくりしたカメラの横揺れなくしてください」）。人物はグリッチだけで出す（「イージング不要で、グリッチ出現のみ」）。
- **裏歌詞（語りの字幕）は画面に出さない**（所有者 11-06「表示する必要がない」）。
- **カバーの伴奏を作り直すときも界隈曲の音で作る**（所有者 11-06・11-07「ミックスの方向性、アレンジの方向性が外れている」「高音によっていて耳が痛い」「曲のクオリティが凡庸、陳腐」）。工場プリセット・サイドチェイン・長い残響・衝撃音や上がる雑音は使わない。音色は 1 音ずつ高さを測ってから使う（「オクターブ高い」「半音ズレている」）。帯域は原曲を測って寄せる。手順は [techniques/ust-cover.md](techniques/ust-cover.md)。
- **合成の歌は声質に合う高さで歌わせ、子音を刻まない**（所有者 11-06「サビはロゼの声質的にワンオク下げたほうがいい」、11-07「子音は刻まないほうがいい」）。落ちた音・弱い音はモーラごとに直す（「『ら』が異様に小さい」）。

## 5. 安全の線

- 性的な語・下ネタの素材は使ってよい（所有者 10-31）。
- 扱わないもの: 暴力や虐待の場面・子どもとして描かれた人物の素材、出演者が嫌がる素材、私生活の詮索。キャラのネタにするときも、性的な台詞と虐げる構図を組み合わせない（bb9 のひでは「倒れない盾」だけにした）。
- 素材・参考動画・原曲・耳コピ・書き出した曲と動画は他の方の作品を含むので、git に入れず公開しない。作業フォルダ（`scratch/`）か手元に置く。
- 投稿先の規約（ニコニコは 2025 年に R-18 の MAD を削除）は投稿前に所有者が判断する。

## 6. 渡し方と確かめ方

- 確認は `FPS=15`、渡すのは 30fps。
- 指定した秒のコマ、全体の一覧画像（ffmpeg の tile）、1秒を細かく並べた帯で、字や顔がモーラと拍に合っているかを見る。
- 6秒ごとの明るさ・動き・音量を測り、区間ごとに段が付いているかを見る（合否ではなく目安）。
- 画像を見るたびに使用量が増えるので、確認は一覧 1 枚で済ませ、コマを1枚ずつ見るのは境目に迷ったときだけにする。
- サムネは専用のコマを作る（[techniques/thumbnail.md](techniques/thumbnail.md)）。
- 台詞の層だけを別に書き出す（voice.wav・click.wav・grid.json・placement.json）。[speech-melody/README.md](../../scripts/speech-melody/README.md) §9-4。
