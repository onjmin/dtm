# 引継ぎ: 自動作曲

自動作曲（`src/compose/`）の現在地・決まったこと・やらないこと・守る不変条件をまとめる。
**作業を始める前に読む。** 一度この文書に気づかず調査を始め、既出の結論を数え直したことがある。
2026-09-16〜10-01 の経緯・試した順番・検算ログ・数値表は git の履歴にある（この文書の旧版を含む）。

## 1. 今の状態（2026-10-01、c7216742 時点）

### 公開しているもの（UI の「構成」に出る）

- 既存テンプレート（`1chorus` / `jpop_standard` / `jpop_drop` / `vocaloid` / `verse_chorus` / `game_loop` など、
  `src/compose/compose-sections.ts`）と、界隈曲テンプレート **`kaiwai`（第4版）**。
- `kaiwai` は旋律の外側（構成・テンポ・調・進行・ベース・ドラム・楽器）をテンプレートで差し替えたもの:
  詠唱型の歌メロ（`form: "chant"`、1〜2小節の型を繰り返す）・4つ打ち・8分オクターブのベース・
  四抜き短音階 `yonuki_minor`・二次ドミナント入りの進行プール `KAIWAI_A/B/C`・
  アルペジオ層はラスサビだけ（`sub: "arpeggio"`）。
- **公開の歌メロ素材は `SYNTH_PHRASES`**（`src/compose/compose.ts`）。モチーフのリズム型 × 2小節目 ×
  輪郭の原型（`MOTIF_ARCHETYPES`、手書き）を決定的に組んだもので、どの曲の断片でもない。
  **音の良し悪しは未確認。** 9/18 以前の「合成の輪郭」に近いので、当時の「キャッチーでない」がまた出うる。

## 2. 決まったこと・やらないこと

### 決まったこと（所有者の判断）

- **目標は「ヒット曲」ではなく「人が手を入れる出発点」**（2026-09-18）。判定は「ゼロから書くより速いか」。
- **耳による旋律方式の採否は止め、旋律の外側へ**（2026-09-19）。→ その外側の入口として `kaiwai` を作った。
- **骨格借用は製品にしない**（10-01）。「パクリ度は別として界隈曲に聴こえる」が「ベースとか同じ物を使っていて
  パクリとかそういう次元じゃない」。
- **耳コピ由来のフレーズ集・バンク・骨格は公開物から外す**（10-01）。継ぎ合わせ seed 87 の冒頭で、歌のリズムが
  全小節・音が 12 音中 10 音元曲どおりに戻ったため。
- 継ぎ合わせの細目: イントロをサビの和音で始めるかは半々で両方出す（界隈曲を分ける要素ではない）／
  ベースの型を和音と別の曲から借りるのは「良い」。
- 音色は足りている（「人力の耳コピはこの DAW の音で界隈曲に聴こえる」）。

### やらないこと（打ち止めにした方向）

- **統計を参考コーパスへ寄せる。** 17指標・隣接音程の分布まで一致して、所有者の評価はコーパス約90%／生成 0/10。
  分布が一致して知覚が分離するので、差は分布にない。
- **旋律の素材（音符列）の差し替え。** 寄せた統計・人間の実在2小節・モデル製2小節・モデルの旋律まるごとの4通りが
  4連敗。ただし後半はよその進行へ旋律だけ載せた形式で、「旋律は無関係」とまでは言えない（疑うなら素材ではなく
  旋律が通る道）。
- **8小節・目隠し・「どちらがましか」の A/B で細かい採否を決める。** 感度検査で、伴奏を三全音ずらす級の粗い差は
  当たるが、旋律を見ずに引いた調内の三和音は出荷版と区別がつかなかった。
- **ドラムの生成器を書く。** 固定パターンから選ぶのが仕様で、2回作って2回取り消された（`pickBuiltinDrum` のコメント）。
  `SectionSpec` に `drumLevel` は無い。
- 「旋律に和声を合わせる」（和音内の割合を上げる）はレバーではなかった（A/B で耳と一致せず）。

### 戒め（scripts のコメントが参照している実測）

- **当たりは統計で選べない。** 所有者が何百回か引いて貼った当たり13本（当たり率 3〜5%）は、速い（テンポ中央値150）・
  ドラムは dance/16beat/disco のみ・同音連打が少ない・16分が二極（0 か多い）だった。だがそれは**選ばれた側の特徴**で、
  「そこへ寄せれば良い曲」ではない。全曲を寄せれば全曲が同じ顔になる。使うなら利用者が選ぶ系統（ゲーム音楽風）として。
- **新しい指標を思いついたら、まず「良い曲と悪い曲を分けるか」を問う。** これまでの指標は1つも分けていない。
  内蔵の `ComposeStats.score` は構造チェックと相関 r = −0.06。到達率（reach）は作風を作れるかで、品質の代理にしない。
- 厚み（発音/秒）を減点に入れたが、根拠が良1本・不可3本だけだったので外した（表示だけ残す）。
- **測定器を検証してから結論を出す。** 4連敗の後半2回は、形式の感度を確かめないまま「差なし」と読んでいた。
- 旋律だけを別の曲の進行へ差し替える実験は、素材が何であれ成立しない（和音とぶつかる）。差し替えるなら和声ごと。
- 審査エージェントに「順位を付けろ」と頼むと、悪い集合からでも勝者が出る。所有者の評価を渡し、
  「この評価を分けているものは何か」を問う形にする。

### 試聴を頼むとき

- **1日5本程度まで**（十数本で「聴きすぎてセンサーがおかしくなっている」と言われた。終盤の評価ほど信頼度が落ちる）。
- 評価用は**全トラック入り**で出す（歌単体では判断しづらい）。人間側の素材は**所有者が知らない曲**を使う。
- 訊くのは採点ではなく仕様: 「出発点として使うか／最初に直す場所／理由を一言」。曲まるごとの聞き取りは
  3曲で明確な反応が出た（3/3「捨てる」、理由は「テーマが無い・耳に訴えるメロディラインが無い」、直す場所は挙げられない）。

## 3. 不変条件

- **既存テンプレートの曲を1音も変えない。** 新しい挙動はテンプレートの省略可能フィールド（`template?.field`）の
  有無で分岐し、無ければ従来の経路をそのまま通す。テンプレート名の文字列比較は書かない。
- **共通経路に `rnd()` / `pick(` を足さない。** 乱数の消費順が変わると全 seed の曲が変わる。
  - 新しい抽選は新しい分岐の中だけで行う。他の型の乱数列を変えたくないときは「抽選してから 0 に潰す」。
  - 既存の進行プール配列に要素を足さない（`pick` の添字がずれる）。
  - `engine === "skeleton"` / `"splice"` は `composeSong` の先頭で乱数を1つも消費せずに分岐する。
  - 継ぎ合わせの「切る置換」の抽選は曲の乱数でなく `positionRandom(donor.src, 位置)`（他セクションの donor を動かさない）。
- **黄金値**: `scripts/test/check-compose.ts` が既定＋6構成 × アプリの種 {1, 4022250974, 3842857959} の
  生成物の sha256 を `scripts/test/fixtures/compose-golden.json` と照合する（21本。骨格データがあれば `skeleton` キーの
  3本も）。**出力を意図して変えたときだけ** `--bless` で取り直す。src を触る前に採っておく。
- **アプリ経路の .mid 一致**: 7構成 × 2種を変更前後で `export-samples.ts --app-seed` で書き出し、sha256 を比べる
  （差分ファイルが空であること）。
- イントロ等のセクション長に奇数を置かない（楽句は2小節単位 `floor(bar/2)` で、以降が全部1小節ずれる）。
- `chordProgression` は基準調（ハ長調 / A マイナー）のまま返し、調は `rootShift` で渡す（二重移調のバグがあった）。
- 耳コピ由来のデータを src に import しない。scripts から options で渡す。
- 2.1.11〜2.1.13 で書き出した MML は読み込むと先頭に余計な音が1つ入る（`#ver=` 宣言の読み漏れ。修正済み、
  `scripts/test/check-mml-meta.ts` で検算）。手元のファイルを読み戻したら先頭の1音を疑う。

## 4. 検算

```
npx tsc --noEmit
pnpm check
pnpm test                                        # check-compose（黄金値・界隈曲・骨格/継ぎ合わせ節）, check-tracks ほか
npx tsx scripts/test/check-compose.ts --bless    # 出力を意図して変えたときだけ
```

- seed の再現（アプリの主旋律と音符単位で一致することを確認済み）:
  `npx tsx scripts/compose/export-samples.ts --app-seed 3842857959 --compose custom:any:auto:intro-verse-prechorus-chorus`
- 試聴用の書き出し: `npx tsx scripts/compose/export-samples.ts --template kaiwai --count 12 --seed 1 --out tmp/kaiwai/samples`
  （ファイル名から調・テンポ・楽器・ドラムの分布が一瞥できる）。
- コーパスとの差（良否ではなく到達）: `npx tsx scripts/corpus/measure-arrangement.ts --generate kaiwai --count 40 --seed 1 --min-bars 40 --min-channels 6`
- 元曲との近さ（手元データが要る。無ければ skip）:
  `scripts/corpus/check-skeleton-closeness.ts --count 40 --seed 1`、`scripts/corpus/check-splice-closeness.ts --count 200 --seed 1`
  （継ぎ合わせは和音列の最長一致・ベース実音・旋律の度数列・同 src 連続を上限で縛る）。
- 形式の感度を測る: `npx tsx scripts/compose/ab-listen.ts --variant broken`（壊した側が負けるか）。
- 未参照のコードを見つけたら、提案の前に `git log -S"<名前>"` で消された経緯を探す（一度入れて取り消した方式が
  散文だけ残っている例が複数ある）。

## 5. 界隈曲の経緯

- `kaiwai` 第1〜2版（構成・ドラム・ベース・音階の差し替え）: 「全体的に界隈曲っぽくない」、4つ打ち＋8分オクターブの曲の
  イントロだけ「若干」。歌メロが入った瞬間に J-POP になる。
- 第3〜4版（詠唱型の歌メロ・二次ドミナント入りの進行・アルペジオはラスサビだけ）: 短尺の1本と最初のサビが「若干似ている」止まり。
- 骨格借用（耳コピの骨格をそのまま使う）: 界隈曲に聴こえたが「パクリの次元」→ 製品にしない。
- 継ぎ合わせ（セクション単位で別々の曲から抽象骨格を継ぐ）: seed 87 が初めて「界隈曲っぽい」。ただし冒頭が元曲の
  丸写し（根音の並び、歌のリズム全一致・音も大半一致）→ データごと公開物から外した。
- 読み: 界隈曲らしさは伴奏の核（4つ打ち・8分オクターブ・ドミナント7th で短調へ引き戻す進行）と、実在の歌メロの
  並び順に載っている。後者を借りると丸写しに近づく。

## 6. 次の一手

所有者の耳と時間を使うものは、着手前に確認する。

1. **公開版（`SYNTH_PHRASES` に戻した歌メロ）を聴いてもらう。** 素材の入れ替えで黄金値は全部変わったが、
   音の良し悪しは誰も聴いていない。
2. 「界隈曲っぽさ」を、耳コピ由来のデータに頼らずに出せるか。伴奏の核は公開版 `kaiwai` に入っているので、
   残りは歌メロ側。所有者の言葉「テーマが無い」「滑り台の位置がイントロから変わらない」はまだ説明できていない。
3. 手元の実験を続けるなら: 継ぎ合わせで丸写し感が残るとき、次の候補は歌メロのリズムと反復の地図を和音と
   別の曲から借りること（10-01 時点の未確認案）。
4. 別の道として、自動作曲の改善を止め、カバー作り・打ち込みの側へ工数を移す案もある（所有者の判断）。

既知の未決（所有者判断）: `kaiwai` のベース帯の閾値・ベース型の配分、伴奏を bpm 120 固定で刻む件
（直すと全テンプレートの伴奏が変わる）、骨格のドラム無し 15 本をそのまま出すか。
