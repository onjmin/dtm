# 引継ぎ: 自動作曲の「キャッチーさ」について

2026-09-16〜18 のセッションの結論と、次にやることをまとめる。
**同じ調査を繰り返さないために読む。**

## 1行でいうと

**統計を参考コーパスへ寄せる方針は打ち止め。** 目標は「ヒット曲」ではなく
「人が手を入れる出発点」に置き直した。

## 何が分かっているか（すべて実測）

### 統計はキャッチーさを分けない

生成物と参考コーパス（`Music/_own/自作/界隈曲` 91本）は、次がすべて一致していた。

- `scripts/compare-corpus.ts` の17指標
- **隣接音程のヒストグラム**（0度 16.5/14.1、1度 10.5/14.5、2度 34.9/36.2 …）
- 反復（`compare-repetition.ts`）はむしろ生成物の方が多い
- `compare-reach.ts` の到達率 75%

それでいて所有者の評価は **コーパス約90%がキャッチー / 生成物 0/10**。

**分布が一致して知覚が完全に分離するなら、差は分布ではなく並び順にある。**
距離を目標にする方式ではこの情報は原理的に入らない。

### 目隠し聴取テストは有効だった

`tmp/blind.ts`。人間（他人の曲）と生成物を、伴奏なし・同じ音色・同じテンポ・
ラベル隠しで混ぜる。**12/13 で分離した**（判断を下した8件中7件正解＋5件中5件正解。
「判断が難しい」と言われた4件は全部生成物だった）。

差はメロディの音符列の中にある、と言ってよい。

**実施上の注意:**
- **1回5本まで。** 24本送ったとき、後半12本は聴かれなかった
- **人間側は他人の曲を使う。** 自作は聞き馴染みが交絡する（最初の版はこれで無効になった）
- 評価用サンプルは**全トラック入り**で出す。メロディ単体では判断が難しい

### 指標を新しく思いついたら

まず「これはキャッチーな曲とそうでない曲を**分けるか**」を問う。
これまでの指標は1つも分けていない。到達率（reach）は「その作風の曲を作れるか」で
あって「良い曲か」ではない。**品質の代理にしないこと。**

### 手順4「耳で選ぶ」は実行できない——バンク単位の A/B へ変えた

README の旧・手順4は「生成したフレーズを耳で選ぶ／**このコストは1回きり**」だったが、
**算数が合っていなかった**。同梱ぶん801種でも、実測の聴取能力（1回5本）では160回。
そのうえ判断の形式も無効で、伴奏なしのメロディ単体では判断が難しいと同じ実測で

代わりに `tmp/ab-bank.ts`。同じ曲を素材だけ入れ替えて2本出し、**5組10本・約3分**で
「モデル製のバンクを採るか」だけを決める。`drawCount: 1` で引くのが肝で、既定の
40本引き＋選抜のままだと素材を変えた時点で勝つ候補が入れ替わり、テンポも進行も
別の曲になる（実測で5組すべて別物）。ドラムと楽器も曲調連動で変わるのでペア内で固定。

**結果: 差が無かった。** 5組10本の目隠し A/B で「どっちも似たようなもん」。
`src/compose-melodies.ts` は同梱せず削除した（バンク自体は `tmp/compose-melodies.ts`
に19,969種、モデルは `tmp/base.pt` / `tmp/melody-model.pt` に残っている）。

### ここから言えること（B-1 の結論）

素材を3通り試して、3回とも耳に届かなかった。

| 素材 | 結果 |
|---|---|
| 統計を参考コーパスへ寄せた旋律 | 17指標も隣接音程も一致して 0/10 |
| **人間の曲から抜いた実在の2小節** | 「良くなっていない」 |
| **1.18億トークンで事前学習したモデル製の2小節** | 人間の実在フレーズと**区別がつかない** |

**人間が書いた本物の2小節を使っても差が出ない**のだから、2小節という単位に
キャッチーさは載っていない。目隠し聴取テストで12/13が分離したのは**曲まるごとの
旋律**で、その差は2小節へ切った時点で失われている、と読むのが筋が通る。

つまり効いていないのは素材の作り方ではなく、**2小節へ切って引き直す枠組み**そのもの。
モデルは任意長の旋律を学んだのに、`generate.py` はそれを2小節へ刻んでいる——
学ばせた「並び順」のうち2小節を超えるぶんを捨てている。

### まるごと書かせても差が無かった（2026-09-19・4つめ）

`tmp/ab-whole.ts`。モデルに2小節へ刻まず旋律を書かせ、その曲の音階・調へ写して
同じ編曲へ差し込んだ（伴奏・ベース・パッド・コード・ドラム・テンポ・音色・小節数は
同一。ハモリは主旋律から導くので両方とも外した）。**結果は「差がない」。**

## 旋律の音符列を変える方向は打ち止め

4通り試して4回とも耳に届かなかった。

| 変えたもの | 結果 |
|---|---|
| 統計を参考コーパスへ寄せる | 17指標も隣接音程も一致して 0/10 |
| 人間の曲から抜いた**実在の2小節** | 「良くなっていない」 |
| 事前学習したモデル製の2小節 | 人間の実在フレーズと**区別がつかない** |
| モデルが**刻まずに書いた旋律まるごと** | 今の作曲の旋律と**差がない** |

**人間が書いた本物の旋律素材を使っても差が出ない。** ここから先「別のコーパス・
別のモデル・別の選抜」を試すのは、この4連敗の5本目になる。やらないこと。

**ただし「旋律は無関係」とまでは言えない。** 目隠し聴取テストでは人間の旋律と
生成物が12/13で分離している。分離するのに差し替えても変わらないなら、**この配線を
通した時点で旋律の違いが埋もれている**という読みが残る（音域の写し方・8小節の切り
出し・和音への合わせ・ハモリ無し・伴奏の厚み）。旋律そのものを疑う前に、旋律が
通っていく道を疑うほうが筋が通る。

## 2026-09-19 追記: 4連敗の測定器が未検証だった

上の表の後半2回（モデル製の2小節・モデルの旋律まるごと）は、`tmp/ab-bank.ts` /
`tmp/ab-whole.ts` の形式——**サビ8小節・全トラック入り・素材だけ差し替え**——で
測っている。この形式が「本当に違うもの」を違うと言えるかは、**一度も確かめていない。**

唯一シグナルが出た測定は目隠し聴取テスト（24小節・伴奏なし・人間対生成）の 12/13 で、
A/B とは長さと伴奏の有無の2点が違う。

### 分かったこと1: 旋律は別の曲のコード進行には載らない

`ab-whole.ts` の10本を、歌がコード＋ベースにどれだけ乗っているかで測り直した
（音価重み。「和音内」＝鳴っている和音の構成音、「衝突」＝和音外で構成音と半音でぶつかる）。

| 組 | A（今の作曲） | B（モデルの旋律まるごと） |
|---|---|---|
| 1 | 和音内 41% / 衝突 11% | 16% / 8% |
| 2 | 61% / 16% | 41% / 30% |
| 3 | 37% / 8% | 29% / 18% |
| 4 | 73% / 2% | 53% / 2% |
| 5 | 35% / 38% | 42% / 33% |

B は5組中4組で和音内が低く、3組で衝突が多い。**A の旋律はそのコード進行と一緒に
生成されたもので、B はよそのコード進行へ後から載せたもの**なのだから当然で、
「差がない」という判定は、噛み合った A と手枷つきの B を比べた結果だった。
これは「旋律は効かない」の根拠にならない。人間の旋律で同じことをしても同じ
（所有者の指摘「不協和音になっている」。移調量を伴奏に当てて選び直しても衝突は
減らなかった＝移調の問題ではなく素材とコードの対応の問題）。

**この配線で旋律だけを差し替える実験は、素材が何であれ成立しない。** 差し替える
なら和声も一緒に差し替える（再ハーモナイズ）か、伴奏を外す。

### 分かったこと2: 人間側の素材は「所有者が知らない曲」でなければならない

他作フォルダ `it_is_used` の旋律を出したら、所有者が1本を「よく覚えてる」と言った。
知っている旋律は「ましか」の判定に使えない。自作を外すだけでは足りない。
以後の人間側は **PDMX**（`tmp/pdmx.jsonl`、18万曲のパブリックドメイン譜面）から
無作為に引く。作風は界隈曲と完全には重ならないことは覚えておく（`docs/dataset-provenance.md`）。
なお 12/13 の目隠しテストも人間側が `it_is_used` だったなら、「人間か機械か」の
判別に聞き覚えが混ざっていた可能性は残る。

### 分かったこと3: 歌だけでは「ましか」を判定できない

伴奏を外した版（8小節・ピアノ）を出したら「メロディライン単体で聴いても判断しづらい」。
`ab-listening-budget` の実測どおり。**良否の判定には全トラックが要る**が、旋律だけを
差し替えると上記1で成立しない。両立させるには**A・B の両方に和声を付け直す**しかない。

### 陽性対照: `scripts/ab-listen.ts`

`tmp/ab-whole.ts` の後継で、`scripts/` へ移して残した。B に**人間の本物の旋律**（PDMX）を
入れ、**A・B とも同じ手続きで和声を付け直して**全トラックで鳴らす。

```
npx tsx scripts/ab-listen.ts --pdmx tmp/pdmx.jsonl --out tmp/ab-pdmx
```

手続き: 元の進行の小節割りを単位にし、調のダイアトニック三和音を候補に「和音内の音価−衝突」
と進行の常套（V→I、IV→V、同じ和音の連続を軽く嫌う）を Viterbi で解く。コードは曲と同じ
奏法、ベースは曲のベースのリズムと根音からの度数を保って新しい根音へ、パッドは時刻を
保って最寄りの構成音へ写す。サブメロとハモリは主旋律から導かれる声部なので両方とも外す。
ハーモナイザの出来は A・B に等しく効くので、独立変数は旋律だけに戻る。

付け直し後の当たり具合（音価重み）。A も元の進行より乗りが良くなっている点に注意——
**今の作曲は、自分で出した進行に自分の旋律が半分しか乗っていない**（後述）。

| 組 | A（今の作曲の旋律） | B（PDMX の旋律） |
|---|---|---|
| 1 | 和音内 63% / 衝突 9% | 81% / 13% |
| 2 | 50% / 11% | 60% / 10% |
| 3 | 78% / 15% | 75% / 6% |
| 4 | 41% / 11% | 84% / 6% |
| 5 | 45% / 3% | 47% / 10% |

### 分かったこと4: 出荷版そのものを対照に置いていなかった

ここまでの A/B は全部「試作 対 人間」で、**main で出荷している出力そのもの**（12本引き＋
選抜・ハモリ・2声・オクターブ重ね・サブメロ・自前の進行・楽器プリセット）は一度も
並んでいなかった（所有者の指摘）。`--release` で1曲につき3本出す。

```
npx tsx scripts/ab-listen.ts --pdmx tmp/pdmx.jsonl --release --out tmp/abc-release
```

| | 中身 | 何が分かるか |
|---|---|---|
| A | 出荷版そのまま（`export-samples.ts` と同じ書き出し。オクターブ重ねだけアプリと同じく1オクターブ下げ） | 基準 |
| B | 同じ曲の同じ旋律を、和声付け直し（ハモリ・サブメロ無し）に通したもの | A−B ＝ **道具の損失** |
| C | PDMX の人間の旋律を、同じ和声付け直しに通したもの | B−C ＝ **旋律の差** |

A≈B が確かめられて初めて、A 対 C を「出荷版 対 人間」と読める。3本とも同じ曲・テンポ・
ドラム・楽器で、順番は組ごとに無作為。

**`tmp/abc-release/` に5組15本。** 答えは `_key.txt`。訊くのは「1・2・3 のどれがましか
（順位）」の1問だけ。15本は予算（10本）を超えるので、**3組目まででも成立する**——
組ごとに3本そろっていれば途中で止めてよい。

| 結果 | 読み |
|---|---|
| A≈B、C が勝つ | 道具は忠実で、人間の旋律は出荷版より良い。旋律の道は閉じない |
| A≈B、差なし | 8小節・目隠しでは「ましか」が決まらない。`--bars 24` へ |
| A≫B | 付け直しか声部の削減が聴感を落としている。B 対 C は読めるが A 対 C は読めない。道具側を直す |
| A≫C だが B≈C | ハモリ・サブメロ・自前の進行の側に価値がある＝旋律の外側が効いている |

`tmp/ab-pdmx/` は A/B 版（出荷版なし）。参考として残す。

#### 結果（2026-09-19、所有者の順位付け）

| 組 | 順位 |
|---|---|
| 1 | C > A > B |
| 2 | B > C > A |
| 3 | A > B > C |
| 4 | B > C > A |
| 5 | A > B > C |

対にすると A 対 B は 3-2、B 対 C は 4-1、A 対 C は 2-3。順位の合計は A 10 / B 9 / C 11。
5組では何も有意にならない（4-1 でも片側 p≈0.19）。読めるのは次の2点まで。

- **A≈B。** 和声の付け直しと声部の削減（ハモリ・サブメロ・自前の進行を外す）は
  聴感をはっきりとは落としていない。道具は出荷版に対して忠実と言ってよく、

- **C は勝っていない。** PDMX の人間の旋律は、同じ道具に通しても出荷版の旋律に

  作風が違う（賛美歌・古典・民謡の頂点8小節をJ-POP風のサビの位置に置いている。
  1組目の C は8小節で25音）ので「人間だから良い」が成り立たない素材だった、と
  読むのが自然。**形式の欠陥とは断定できない**が、形式が生きている証拠も得られなかった。

つまり **「旋律は効かない」は撤回も確定もできないまま**。人間の旋律で形式を検証するには
「所有者が知らない・作風が界隈曲に近い」素材が要り、手元には無い（自作は聞き馴染み、
他作 `it_is_used` も聞き馴染み、PDMX は作風違い）。

次の候補（どれも所有者の耳を使うので、着手前に確認する）:

1. **PDMX を作風で絞る**（1小節 6〜9 音・16分あり・音域 17 半音以内・4/4）。
   それでも「界隈の本物」ではない
2. **`--bars 24`** で長さを戻す（3組9本で約7分）。差が8小節より長い構造にあるという読みの検証
3. **耳による方式の採否はここで止め**、旋律の外側（編曲・音色・構成・歌詞・「合わせ方」）へ移る。
   A≈B が出たので、出荷版の全部入りも8小節では効いていない＝そこにも伸びしろがある

| 結果 | 読み | 次 |
|---|---|---|
| **人間が勝つ** | 成立する形式なら差は聞こえる。ab-whole の「差なし」は形式の欠陥（上記1）。旋律の道は閉じない | 同じ形式で `--model tmp/whole-melodies.jsonl`。モデルが人間に届くかを測り直す |
| **差がない** | 8小節・目隠しでは「ましか」が決まらない | `--bars 24` で長さを戻す。それでも差がなければ耳による方式の採否は打ち止め |

### ついでに見えたこと: 今の作曲の旋律はコードに半分しか乗っていない

`ab-whole.ts` の A（今の作曲そのまま）は和音内 35〜73%、半音衝突 2〜38%。上の表の
付け直し後でも 41〜78%。歌メロが構成音に乗る割合としては低い（B の PDMX は 60〜84%）。
`compose.ts` の旋律は和音を「重み」でしか見ていない（`CHORD_TONE_WEIGHT`・`toneWeight`）
ので、経過音・テンションが多くなる。**「メロディと伴奏の合わせ方」は旋律の外側の候補
として、陽性対照の結果と無関係に測る価値がある**（ただし数字を寄せるだけなら
`statistics-cannot-predict-catchiness` の二の舞。A/B で耳に問うこと）。

## 残っている筋

`tmp/abc-release/` は聴き終わった（上記）。撤回も確定もできず、素材の問題で止まっている。
**2026-09-19、所有者の決定で候補3（耳による旋律の採否はここで止め、旋律の外側へ）を採った。**

### 旋律の外側・第1手: 和声だけを変える（`--variant chords`）

A/B/C で B が A に勝った2組は、**付け直しで和音内の割合が大きく上がった組**（38→64%、
49→59%）と一致していた。5組中2組なので弱いが、この一連の実験で唯一「何かと一致した」
信号。旋律を固定して和声だけを入れ替え、直接測る。

```
npx tsx scripts/ab-listen.ts --variant chords --seed 20260920 --out tmp/ab-chords
```

| | 中身 |
|---|---|
| A | 出荷版の旋律 ＋ 出荷版の進行・ベース・パッド（ハモリ・サブメロは和音から導く声部なので両方とも外す） |
| B | 同じ旋律 ＋ 旋律に合わせて付け直した進行・ベース・パッド |

`tmp/ab-chords/` に5組10本（A/B/C とは別の seed。聴いた曲を再利用しない）。
訊くのは「1と2のどちらがましか」の1問だけ。

| 結果 | 次 |
|---|---|
| B が 4-1 以上 | 「旋律に和声を合わせる」が製品側のレバー。`compose.ts` の進行プールを旋律の後に再解決するか、`ComposeResult.chordProgression` の後処理として入れる。ハモリ・サブメロは新しい和音から引き直す |
| 差がない | 和音内の割合も耳には出ない。次は編曲（層の出し入れ）・音色（プリセット）・構成の順 |

**出荷版の進行は旋律に乗っていない**（この物差しで和音内 31〜62%、衝突 20〜32%。7th で
衝突が多めに出る物差しではある）。`compose.ts` は進行を先に引き、旋律は和音を「重み」でしか
見ないので、こうなる。

#### 結果（2026-09-19）: 差なし。和音内の割合は耳と一致しない

| 組 | 判定 | 和音内 A→B |
|---|---|---|
| 1 | A | 54→70% |
| 2 | 引き分け | 20→33% |
| 3 | A | 44→48% |
| 4 | 引き分け | 78→66% |
| 5 | B | 74→56% |

A 2 / B 1 / 引き分け 2。**和音内が最も上がった組で A が勝ち、A のほうが高い組で B が
勝った。** A/B/C で見えた「付け直しで和音内が上がった組が勝つ」は偶然だった。
「旋律に和声を合わせる」はレバーではない。出荷版の 7th 進行は、旋律に合わせた三和音に
少なくとも負けていない。

### この形式で差が出たものが一つも無い

| 変えたもの | 結果 |
|---|---|
| 旋律の素材（4通り） | 差なし |
| 全部入り（ハモリ・サブメロ・自前の進行）対 声部削減 | A≈B（3-2） |
| 人間（PDMX）の旋律 | 勝たず（1-4） |
| 和声だけ | 差なし（2-1-2） |

「全部本当に効かない」のか「8小節・目隠し・どちらがましか、という形式が何も聴き分けられ
ない」のかを、ここで切り分ける。**必ず聴き分けられるはずの差**を同じ形式で出して当てられる
かを見る（`--variant broken`。奇数組は旋律を見ずに無作為に引いた三和音、偶数組は伴奏だけ
三全音ずらし）。

```
npx tsx scripts/ab-listen.ts --variant broken --seed 20260921 --out tmp/ab-broken
```

| 結果 | 読み |
|---|---|
| 壊した B が 5組とも負ける | 形式は生きている。上の「差なし」は本物で、8小節の聴感を動かすものが見つかっていない。次は編曲（層）・音色・構成 |
| 三全音は当たるが無作為三和音は当たらない | 形式は粗い差しか拾えない。細かい採否には使えない |
| 三全音も当たらない | 形式を捨てる。耳を使うなら曲まるごと・伴奏付き・別の質問（「どちらを直したいか」など）へ |

#### 結果（2026-09-19）: 三全音は当たり、無作為三和音は当たらない

| 組 | 壊し方 | 判定 |
|---|---|---|
| 1 | 無作為三和音 | A（出荷版）が勝ち |
| 2 | 三全音ずらし | A が勝ち |
| 3 | 無作為三和音 | **B（壊した側）が勝ち** |
| 4 | 三全音ずらし | A が勝ち（「不協和音」と指摘） |
| 5 | 無作為三和音（偶然協和） | 判定不能 |

三全音は 2/2 で当たる。無作為三和音は 1 勝 1 敗 1 不能で当たらない。**調の中の三和音なら、
旋律を見ずに引いた進行でも出荷版の進行と区別がつかない**。この形式（サビ8小節・目隠し・
「どちらがましか」）が拾えるのは、伴奏が調から外れる級の粗い差だけ。

### 結論: 8小節の目隠し A/B は細かい採否に使えない

旋律の素材（4通り）・声部の数・人間の旋律・和声の選び方は、どれもこの形式の分解能の下に
ある。**「全部効かない」のではなく「この測り方では何も見えない」**。ここから先、
同じ形式で編曲・音色・構成を測っても「差なし」が続くだけなので、**やらない**。

残る耳の使い道は、目標（`compose-goal-is-editing-starting-point`）に直接対応する問い。
「どちらがましか」ではなく、曲まるごとを聴いて**「これを出発点に手を入れるなら、どこを
直すか／ゼロから書くより速いか」**を訊く。これは採点ではなく仕様の聞き取りで、
1曲ずつでよく、目隠しも要らない。

`scripts/ab-listen.ts` は残す（陽性対照・感度検査・和声付け直しの道具として再利用できる）。
`tmp/ab-*` `tmp/abc-*` は消えてよい。

旋律の外側。目標は「人が手を入れる出発点」（`compose-goal-is-editing-starting-point`）
なので、価値は引き直しと編集の側にある。

- **引き直しUX の残り**（下記）。スマホで「たくさん引いて選ぶ」を成立させる設計
- 編曲・音色・構成・歌詞の側。ここは一度も測っていない

学習パイプライン（`tools/melody-model/`）はそのまま残す。**結論は否定的だが配線と
実測値は揃っている**ので、旋律の外側を変えたあとで効き方が変わるなら再利用できる。

### 引き直しUXの残り

スマホ前提で「たくさん引いて選ぶ」を成立させる設計。候補を並べるUIは成立しない
