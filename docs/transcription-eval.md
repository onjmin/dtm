# 自動採譜（耳コピ）の評価実験

2026-09-30。「wav/mp3 を入れて MML に書き起こす耳コピ機能は高精度で実装可能か」に、
手元の対になったデータで答えるための実験。道具は `scripts/transcribe/eval_transcription.py`、
結果は `tmp/transcribe-eval/summary.md`（gitignore。本書に写してある）。

## 1行でいうと

**今の公開モデル（Demucs 分離 → Basic Pitch 採譜）で、歌とベースは音符の半分、伴奏は3分の1が
人力の耳コピと一致する。テンポは 1% 未満で当たり、4つ打ちのキックは拍を当てているだけ。**
「全パートを人力並みに」は無理で、「下書き（テンポ・調・歌とベースの半分・和音の半分）を出して人が直す」が現実の水準。

## 手順

1. Demucs htdemucs（GPU、乱数固定）で vocals / drums / bass / other に分離。
2. Basic Pitch（ONNX、CPU）で vocals・bass・other・ミックスを採譜（最短音長 58ms。既定 127.7ms にすると曲により ±0.08 動く）。
   ドラムは drums 系統の打点検出＋帯域エネルギー比の多重ラベル（キック／スネア・クラップ／ハット）。
3. **位置合わせ**: 正解 MIDI は音声とテンポ・小節頭・調が一致している保証が無い（とべない深海魚は
   MIDI 140 BPM・実音源 144 BPM）。正解の音符から作ったクロマ列と音声のクロマ列の相互相関で
   倍率（0.97〜1.03）・ずれ（±20秒）・移調（半音）を同時に推定し、ずれだけ打点包絡で 16分の半分未満の範囲で詰め直す。
   **打点だけの位置合わせは4つ打ちの周期性で 5曲中2曲が拍単位に外れた**（その位置では F1 が 0.05 に落ちる）。
4. 正解のパート分けはトラック名（ウタ／Vocal 等）を優先。ヤツメ穴は歌が「ウタ」「ころんば4号」の2トラックに
   割れているので、歌は「声もの全部」（ハモリ・コーラス込み）を主指標にする。打楽器を音程トラックに書いたもの
   （嵌り合う体は の「Drum」p113）は楽器の正解から外す。
5. mir_eval で音符 F1（オンセット ±50ms・音高 ±50セント・オフセット無視）。クロマ F1 はオクターブを無視。

## 「余計な音」の内訳（検証エージェントの再計算）

リード歌の未一致推定音のうち、正解の別の声トラック（Vocal_2・Chorus）に当たっている音が 3曲で 29〜36%
（＝正しい採譜で、正解をリード1本に限った定義の問題）。極短音（<127.7ms）が 23〜50%、無音区間の幻が
ヤツメ穴 192/788・あねもね 97/387。楽器（other）の推定音は 6割強がどの正解トラックにも当たらない（倍音・分離漏れ）。

**単純な後処理では上がらない**（`scratch/cleanup_bound.py`）: 細切れ結合・オクターブ重複除去・単旋律化・16分量子化を
どう組み合わせてもリード歌の平均 F1 は 0.45〜0.47 のまま、ベースは 0.44→0.35 に下がる。
最短音長を Basic Pitch 既定（127.7ms）に戻すと あさやけ 0.66→0.74、あねもね 0.37→0.31 で曲による。

## 但し書き

- 5曲とも 130〜144 BPM の歌もので、正解は完成品に偏る。テンポ推定の「1% 未満」は 120 中心の事前分布の下での
  値（一様事前だと 2/5 が倍テンポに出る）。
- 調は KS 推定の長短調判定が割れるだけで、音高クラスの分布は 5曲とも移調 0 で相関 0.94〜0.99。
- 三和音一致は正解側も推定（MIDI の音からの三和音当てはめ）なので目安。1小節窓だと位相で 2倍動くため半小節窓にした。
- 分離は乱数シフト付きなので固定してある（固定前は `--force` のたびに小数3桁が動いた）。
- Windows では basic-pitch が CPU 版 onnxruntime を引き込み、`onnxruntime-gpu` を上書きする（この実験で一度壊し、戻した）。
- 実行時間は 1曲 60秒前後（Demucs GPU 10秒、Basic Pitch CPU 3〜4秒×4、位置合わせ 30秒）。5曲で 5〜6分。

## 答え

| 問い | 答え |
|---|---|
| 人力の耳コピ並みに全パートを自動で | 無理。楽器（内声・アルペジオ）は 0.3、歌・ベースで 0.5 |
| 下書きとして使えるか | テンポ・調・歌とベースの半分・半小節の三和音の半分は出る。「人が直す出発点」の水準 |
| 上げ代はどこか | 音源分離と採譜モデルの側（YourMT3+ 級の多楽器モデル、歌声専用の f0 追跡、ドラム専用モデル）。後処理では上がらない |
| 界隈曲固有の難しさ | 歌声の加工（囁き・UTAU）と、同じ矩形波が何声も重なる伴奏。ドラムは 4つ打ちで拍は簡単だが音色分類は曲ごとのキットに依存 |

次にやるなら（どれも所有者の判断待ち）:

1. 採譜モデルを差し替えて同じ5曲で測る（YourMT3+ / MR-MT3 の多楽器出力を分離なしで）。評価器はそのまま使える。
2. 曲数を 21組全部に広げる（`candidates.json` の complete）。1曲 60秒なので 20分。
3. 作者が .ptcop を公開している曲はプロジェクトを直接読む（無損失）。

## 再現

```
PYTHONIOENCODING=utf-8 python scripts/transcribe/eval_transcription.py inventory --audio "C:/Users/frgk2/Music/_own/他作/界隈曲" --midi "C:/Users/frgk2/Music/_own/自作/界隈曲" --out tmp/transcribe-eval
PYTHONIOENCODING=utf-8 python scripts/transcribe/eval_transcription.py run --pairs tmp/transcribe-eval/pairs.json --out tmp/transcribe-eval
```

`pairs.json` は `[{"name", "title", "audio", "midi"}, ...]`。各曲の `transcribed.mid`（歌・ベース・その他・ドラムの4トラック）は
DAW の MIDI 読み込みでそのまま聴ける。
